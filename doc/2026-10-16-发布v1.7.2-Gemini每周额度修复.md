# v1.7.2 Gemini 每周额度修复发布记录

日期：2026-10-16

## 问题现象

Gemini 卡片只显示 5 小时滚动额度，每周额度消失。

## 根因

两个 Antigravity 配额端点对 `retrieveUserQuotaSummary` 返回的分组集不同（2026-10-16 本机实测）：

| 端点 | 返回分组 |
| --- | --- |
| `daily-cloudcode-pa.googleapis.com` | 仅 `Claude and GPT models` 一组 |
| `cloudcode-pa.googleapis.com` | `Gemini Models` + `Claude and GPT models` 两组 |

旧逻辑把 daily 端点排在第一且首个 2xx 响应即采用，于是永远只拿到 Claude/GPT 组；按 `displayName` 含 "gemini" 过滤组的匹配落空，静默降级到 `fetchAvailableModels` 按模型聚合的回退路径——该路径数据源里每个模型只有 5 小时重置信息，结构上永远产不出每周窗口。端点顺序源自接入初期的观测（当时 daily 返回 Gemini 组），上游分组归属变化后此处断链。

## 修复内容

- 端点调序：`cloudcode-pa` 排前（Gemini 组只在该端点），daily 兜底；`fetchAvailableModels` 两端点均可用。
- 汇总接口不再「首个 2xx 即用」：逐端点解析，直到某个响应解析出 Gemini 组；全部没有才走按模型回退，防上游再次变化。
- 组选择规则：优先 `displayName` 含 `gemini models` 的正主组；没有才退第一个含 `gemini` 的组（防 `Gemini 4 Argon` 之类变体乱序抢先）。
- macOS / Windows 两侧同构修改；组解析抽成纯函数（`parseGeminiGroupWindows` / `ParseGeminiGroupWindows`）并补单测，含「daily 形状响应无 Gemini 组 → 返回 nil」的回归守卫。
- macOS / Windows 版本号统一升级到 1.7.2。

## 验证

- macOS 全量自动化测试 187 项通过，0 失败（新增 4 项组解析测试）。
- Windows 侧本机无 WindowsDesktop SDK 无法编译运行，已做语法校验；测试随 CI 执行。
- 线上端到端复现：按新逻辑请求，`cloudcode-pa` 首个端点即命中 `Gemini Models` 组，weekly（已用 4.4%，10-22 重置）与 5h（0%，当日重置）两窗齐返，与 Antigravity IDE 用量面板一致。
