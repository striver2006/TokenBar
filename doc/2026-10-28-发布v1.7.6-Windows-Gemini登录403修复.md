# v1.7.6 Windows Gemini 自有 Google 登录 403 修复发布记录

日期：2026-10-28（本机时区）

## 发布内容

- **Windows**：修复设置页「使用 Google 账号登录」弹出 Google 403 禁止访问页（restricted_client: Unregistered scope `https://www.googleapis.com/auth/aicode`）。根因：agy 二进制内嵌多个 OAuth client（本机实测 3 个 ID × 3 个 secret），运行时扫描结果做交叉乘积配对后盲取第一个发起授权，而该 client 未注册 `aicode` 受限 scope。
- **Windows**：登录前对候选 client 逐个轻量探测甄别（GET 授权 URL、禁用重定向、只看 302 Location——跳到 `signin/oauth/error` 的跳过，几 KB 流量）；全被拒或探测不了时退回原行为。
- **Windows**：授权码交换遇 `invalid_client` 时自动换同 ID 的其他 secret 候选重试（授权码只绑定 client_id，secret 可换）；token 刷新候选上限 3→9 覆盖全部交叉配对——此前真配对本机排第 4 位，`Take(3)` 永远轮不到，本地凭证链过期后刷新会一直失败。
- 双端包版本统一为 1.7.6；Mac 本次无代码变更。

已完成双站发布及本机安装。

## 根因与验证方法

- 本机 `agy.exe` 扫描出 3 个 client ID 与 3 个 secret（交叉乘积 9 组）；用本地 `gemini:antigravity` 凭证的 refresh_token 对 9 组逐一做刷新测试，**仅 1 组可用**（`1071006060591-…` × 对应 secret），其刷新返回的 scope 恰为登录 scope 全集（含 `aicode`）。
- 授权端点对照实测（无 cookie 裸 GET，禁用重定向）：
  - `884354919052-…`（旧逻辑盲取的第一个）→ 302 到 `signin/oauth/error`，即用户看到的 403 页；
  - `1071006060591-…` → 302 到 `v3/signin/identifier` 正常登录页。
- 修复后用正式构建 DLL 真实调用 `PrepareGoogleLoginAsync`：选中 `1071006060591-…`（自动跳过被拒的 `884354919052-…`，探测拒绝记录写入 tokenbar.log），复核 302 指向登录页。
